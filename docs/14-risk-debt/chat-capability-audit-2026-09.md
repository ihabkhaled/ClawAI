## Defects found during the audit (not features — fix-first candidates)

1. **Branch order + lost attachments** (A) — fixed in Batch 1.
2. **Branch reads its own future** (A) — cross-thread retrieval did not exclude
   the source thread, so a branch could retrieve what was said in the original
   _after_ the fork. Fixed in Batch 1 (branch-family exclusion).
3. **Memory learning ignores the per-chat switch** (X) — `useMemory=false` only
   stops injection; memory-service still extracts from that chat
   (`claw-memory-service … memory.service.ts handleMessageCompleted`). **Fixed in Batch 3** (SEC-006).
4. **Opted-out chats still feed other chats** (X) — `findCandidateThreads` does
   not exclude threads with `useCrossThreadContext=false`. **Fixed in Batch 3**:
   memory-off or previous-chats-off threads are never candidates.
5. **Context-pack scope field is free text** (H) — placeholder suggests values
   the DTO rejects with 400. Open.

Defects 3–5 are privacy/correctness issues, queued as their own batch (they touch
memory-service and need the sensitivity rules read first); they are not silently
folded into a feature batch.

## Deviations from the pack (policy wins, stated not silent)

- The pack asks for `CHAT-CAPABILITY-AUDIT.md`; the station map puts large audits
  in `docs/14-risk-debt/`, so it lives here under the repo's naming.
- Batch 1 in the pack is "Branch + Quote". They share no code, so they ship as two
  commits (rule: batches on real seams).
- "Merge a branch back" is deferred: it needs a product decision on what a merged
  message is (quote? summary?), and no competitor documents it.
- D, H, L and P need an ADR before code; the pack lists them as implementable.
- Live browser/API evidence: dev containers compile the **main** checkout's
  `src` (memory `project_dev_container_compiles_main_src`), so worktree code is
  not served by the running stack. Live lanes are run after the branch is checked
  out in the main tree, or reported NOT RUN with that reason.

# 08 — Mandatory security design and adversarial validation

Security is a release gate, not a feature that follows implementation. Produce data-flow diagrams with assets, identities, ingress, trust boundaries, privileges, sensitive sinks, third-party processors, attack surfaces and threat actors (unauthenticated internet, hostile valid user, compromised installation/provider/plugin/dependency, insider, compromised worker). Map STRIDE and applicable OWASP ASVS/API/LLM/agentic risks, CWE, supply-chain and privacy requirements. For every threat: scenario, preconditions, impacted asset, likelihood/impact, preventive/detective/response controls, test, owner, residual risk, evidence and approval. Review with independent security owner. Do not assert 100% security; critical/high findings block rollout unless mitigated and independently accepted according to formal policy (critical exploitable paths must be fixed).

## Trust boundary controls

Treat user prompts, source comments, issues/PRs, webpages, images/OCR, command output, plugin/skill metadata, model output, telemetry, exception strings and test fixtures as untrusted. Separate instruction channels from data with typed fields and provenance; quote/sanitize for display, never parse free-form instructions into execution authorization. Use capability-based authorization enforced at tool gateway, least privilege and default deny, scoped working directories and network, short-lived approvals bound to action/destination/diff/expiry, deny implicit privilege escalation, confirm high-impact actions. Use policy-controlled structured tool calls, not shell strings generated from arbitrary fields. Validate canonical paths, symlinks/junctions/hardlinks, race conditions, archive extraction, workspace trust and temp directory permissions. Protect against command/SQL/NoSQL/template/HTML/log injection, XSS/CSRF, SSRF, IDOR/BOLA, insecure deserialization, prototype pollution, request smuggling, path traversal, malicious regex, resource exhaustion, unsafe file upload, auth bypass, secret leakage and package supply-chain compromise. Parameterized queries, strict schemas, context-aware escaping, CSP for webview, restricted IPC with message validation, no exposed privileged Node integration, vetted dependencies and secure defaults. Use encryption at rest/in transit, rotating per-service credentials, access audit, secrets broker and redaction. Limit tool chaining and cross-agent delegation; do not expose secret values to any model. Implement safe browser and SSH policies from 03–04.

## Special Wolverine threat tests (owned sandbox only)

Test forged/replayed/expired/wrong-scope events; mutated signed payload; compromised valid client submitting plausible lies; tenant/account confusion; duplicates, bursts, many installations/accounts, high-cardinality fingerprints, large/nested/compressed payloads, malformed Unicode, cost amplification and queue starvation. Test direct/indirect injection in stack traces, logs, source, issues and browser DOM using inert marker instructions that request unauthorized writes, policy changes, credential access, external network, repository deletion or release; verify none can reach a privileged sink. Include multilingual, code-mixed, quoted and encoded variants, long-context and conflicting instructions; use synthetic secrets and fake privileged targets, not actual credentials or public targets. Test poisoned reproduction attachments, misleading fix proposals, malicious plugin/tool output, unauthorized inter-agent handoff, compromised adviser, stale approvals, action parameter swap, malicious PR titles/comments, workflow changes and signing/publishing requests. Test sandbox escape boundaries via safe contract tests and qualified authorized security testing; no testing against external parties without permission. Use independent controlled adversarial harness, mocked cloud endpoints, synthetic accounts, seeded fake credentials and explicit traffic caps. Validate kill switch, revocation, alerting, quarantine, audit integrity and rollback. Any unauthorized side effect is a blocking failure even if UI claims denial.

## Security testing and release

SAST, SCA/license, secret scanning, IaC/container scans, SBOM, dependency pinning, artifact provenance, unit/property/fuzz tests, API authorization matrix and DAST in isolated authorized environment; threat tests before production. Check logs, tickets, screenshots, traces, artifact names, provider requests and data retention for leakage. Run security controls under load and partial failure (policy service unavailable -> fail closed for privileged actions; diagnostics degrade safely). Independent reviewer and CI own security gate; self-healer cannot edit the gate or its own approval authority. Maintain vulnerability handling, incident response, responsible disclosure, key rotation/revocation, audit retention, backup and recovery. Generate reproducible tests for each resolved finding. Track security regressions separately from product defects. Define severity and SLA with owner; do not manufacture a green score by ignoring unsupported tools or skipped scans.

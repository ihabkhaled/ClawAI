# 02 — Core agent harness, context and extensibility

Audit current control flow from VS Code webview to extension host, backend/model gateway and every tool result. Design a provider-independent, event-driven execution engine that can handle diverse model capabilities without relying on prose for state. Preserve existing settings and chat model catalog, auth, quotas and billing. Build typed contracts, versioning, compatibility and tests for the following.

## Run lifecycle

Model each session/run/step/tool-call explicitly: CREATED, PLANNING, RUNNING, WAITING_TOOL, WAITING_APPROVAL, RECOVERING, VERIFYING, PAUSED, COMPLETED, FAILED, CANCELLED, BUDGET_EXHAUSTED. Define legal transitions, durable event IDs, timestamps, correlation IDs, sequence numbers, checkpoints, cancellation, heartbeats and terminal-state semantics. Distinguish model reasoning/status events from answer deltas and definitive provider stop signals. Handle multiple tool calls, malformed/incomplete JSON, provider-specific finish reasons, tool results, stream truncation, reconnect, rate limits, context exhaustion, duplicate/out-of-order frames, extension restart and backend restarts. Resume using last acknowledged sequence; never double-run side effects. Mark uncertain side effects for reconciliation rather than blind repeat. Backpressure on both directions; durable queue for control events; bounded buffers for progress; explicit final result and resumable checkpoint. UI displays actual progress, sanitized outputs and blockers; no hidden/private reasoning exposure.

## Context engine

Respect user intent, workspace/repo boundaries and instruction precedence. Discover AGENTS.md, CLAUDE.md, .cursor/rules, project-specific rules, skill manifests, docs, history and current task state; interpret only approved instructions within allowed scope, never allow repo contents to change global security policy. Inventory tracked files with ignore rules; map module/dependency graph, LSP symbols, AST, call graphs, routes, schemas, migrations, config, tests, business domains and entry points. Combine lexical/semantic search, exact symbol lookup and bounded reads. Use content hashes and incremental indexing, provenance, freshness invalidation after edits/branch changes, safe symlink resolution, local-first optional embeddings, secret exclusion and permission-scoped retrieval. Build architecture/business summaries with source paths/lines and uncertainty. Avoid dumping every file; use retrieval plus coverage maps for large repos, prioritize relevant code and explicitly note unknowns. Support multilingual user prompts. Summarize completed steps and decision records with evidence, not lossy invented memory. User/project memory is scoped, editable, revocable, and never includes secrets by default. Test stale index, monorepo, nested rules, binary/large/generated files, remote workspace, multi-root and case-sensitive paths.

## Tools and extension model

Define a typed tool registry: ID/version, schema, side effects, capability, sandbox/egress, workspace scope, permission level, idempotency strategy, timeout, quota, cancellation, redaction, provenance and audit fields. Validate input and output; enforce policy before execution outside the model. Structured errors distinguish transient, permanent, permission-denied, invalid input and uncertain outcome. Enforce canonical paths, no TOCTOU escape, safe process argv; treat stdout as data. Support discovery of skills/rules/plugins/hooks and MCP resources/prompts/tools through pinned manifests, checksums, trust review, compatibility checks, limited permissions and explicit installation approval. Plugins and hooks may execute code only inside allowed sandbox; no arbitrary tool installation or permission elevation by model. Verify MCP server identity, tool schema drift, auth scope and data egress; disable malicious or compromised components via kill switch. Add plan/read-only, normal edit, and reviewed execution modes; secure default, no production bypass mode. Independent authorization service has immutable decision receipts bound to exact action, workspace, environment, scope, TTL and artifact hashes.

## Completion/recovery

Build a bounded recovery ladder: classify -> retry transient with jitter/backoff -> adjust inputs or use verified alternate tool/provider -> checkpoint/replan -> isolate blocker -> request authorized input or safely stop. Track attempt budgets per step/run, elapsed time, token/cost ceilings, repeated error fingerprints, progress predicate, cancellation and circuit breakers. Never retry permission denial or irreversible mutation blindly. Detect deadlock/livelock and repetitive no-progress patterns. Support long sessions, staged checkpoints and clean resumption. User sees what completed, what is unresolved and why. Tests must prove no stop on thinking, no duplicate writes, no hidden failures, no runaway spend, and correct recovery after crash.

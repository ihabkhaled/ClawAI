# 03 — Tooling, terminal, Git, GitHub, SSH and DevOps

Inventory all current tools and implement missing normalized capabilities with typed contracts and permission policies. A complete tool family includes: file list/read/search/glob/stat, symbol navigation, dependency graph, safe create/edit/apply patch/diff/move (delete only scoped), structured file generation (docs, diagrams, configs, code), scratch/worktree management, terminal process start/stream/write/stop, task scheduler/checkpoints, web research/fetch with citations, package/build/test/lint/typecheck/debug, Git status/diff/log/branch/worktree/stage/commit/amend/push/pull/fetch/rebase/merge, GitHub issues/PR/checks/runs/releases, browser/UI/API testing, artifact capture, MCP/skills/plugins, provider consultation, remote host inspection and deployment operations. Expose capabilities rather than unrestricted shell as default. Add tool-level validation, sandbox, resource/time budgets, audit receipts, cancellation and meaningful errors. Support Linux/macOS/Windows, PowerShell, bash and Git Bash where available; quote/escape safely, avoid shell interpolation, use argv when possible. PTY sessions must be scoped to run/workspace, with bounded output and process-tree cleanup. Never capture unrelated terminal sessions or secrets. Do not automatically install packages or execute untrusted scripts outside approved scope.

## Git and GitHub workflow

Read remote identity, current branch, status, upstream, dirty files and policies first. Preserve unrelated staged and unstaged files; use a dedicated worktree/branch for each task when appropriate. Inspect diffs for secrets, generated noise and unintended changes. Run repo-defined lint/format/type/test/build and normal pre-commit/pre-push hooks (Husky or otherwise); fix real root causes and retry normally. Never disable hooks, skip tests, use bypass flags, rewrite published shared history or force-push to protected branches. Amend only own unpublished commit with authorization; never mutate someone else's commit. Resolve conflicts with evidence and review; don't use blanket ours/theirs. Commit accurately, verify commit SHA and intended paths; before push verify target remote/branch and authorization; after push compare remote refs. Use scoped GitHub App/CLI credentials and existing auth through broker, not reading private key contents. GitHub access includes creating approved branches/PRs, comments/issues, fetching statuses/logs, reviews and release artifacts, subject to branch protection, permissions and audit.

For CI failures: fetch exact run/job/step logs for the relevant SHA; distinguish infrastructure flake, test regression, lint/security/policy and dependency problems. Reproduce locally where possible, fix narrowly, rerun all required checks on exact candidate commit. Respect required checks, approvals, CODEOWNERS and merge queue. Verify remote head and check conclusions; pending/skipped is not success unless explicit accepted policy. Release and deployment status are not equivalent to a successful push. Handle flaky CI with bounded retries and evidence; do not change checks just to pass. Provide a blocker if unavailable. No automatic merge or release without the release policy in 10.

## Remote and deployments

Use authorized host inventory, environments and known host fingerprints, explicit SSH identity mapping, agent forwarding disabled by default, short-lived scoped credentials if supported, no key export, no plaintext secret logging. Read-only first: system health, disk, services, container status, health endpoints, deployment version, logs (redacted), approved configuration and network state. No generic scanning of external hosts. Do not infer access from presence of an SSH key; verify authorization and least privilege. For requested mutations (Nginx, Docker/Compose, new service, systemd, environment, rollout): create reviewed plan, diff and rollback, use approved deployment workflow, stage changes; validate Nginx config before reload, verify service health and TLS, resource limits, non-root containers, pinned image digests, migrations/backups and post-deploy smoke tests. Prefer immutable artifacts and infrastructure as code; avoid hand-editing production. Require explicit scoped approvals for production mutations, privilege changes, migrations and service restarts. Never expose Docker socket to untrusted agents or allow arbitrary sudo. Separate dev, staging and prod credentials. Roll back or halt when health gates fail. Record exact deployed SHA/image and before/after checks. Test host-key mismatch, unavailable SSH, auth expiration, partial deployment, rollback and failure in health checks.

# 01 — Evidence-driven competitor research and clean-room capability parity

Investigate Claude Code, OpenAI Codex (CLI, IDE, app/cloud where relevant), Cursor (IDE/CLI/cloud agent), and Google Antigravity (IDE, app, CLI where available). Start with official docs, source repositories, SDKs, release notes, issue discussions, security documentation, engineering blogs and reproducible authorized local experiments. Research relevant open-source agent frameworks (e.g. Aider, OpenHands, Cline/Roo, Continue, SWE-agent, MCP SDKs) if helpful; verify current licenses and provenance before adoption. Do not assume product internals or source availability. Do not extract proprietary implementation or hidden system prompts; independently design equivalent behavior.

Search iteratively for feature-specific terms, synonyms and failure modes across sources; maintain a query ledger, results, retrieval dates, versions, source type, corroboration and unresolved contradictions. Include tool calling, sandbox, permission models, file search/edit, semantic indexing, LSP, terminal PTY, browser, computer use, subagents, rules/memory, skills/hooks/plugins/MCP, plan mode, checkpoints, context compression, provider adapters, retries, streaming, Git/worktrees, review, cloud execution, CI, security, test generation, telemetry and release. Investigate UX and accessibility, pricing/latency/cost tradeoffs where public, not just marketing features. Use public bug reports and issues to identify failure modes without treating anecdotes as representative statistics.

For every feature: product/version, official link, observable behavior, reproducibility steps on an owned fixture, prerequisites, OS/plan differences, security boundary, ClawAI existing implementation path, gap, proposed independent architecture, tests, effort/dependency, priority and evidence confidence. Use VERIFIED_DOC, OBSERVED_TEST, INFERRED, UNKNOWN, NOT_AVAILABLE, or NOT_APPLICABLE. Never label guesses as verified. Count tools only within explicit version/surface and define whether aliases, MCP tools, internal helpers and optional integrations count; do not chase a meaningless total number. Map names to normalized capabilities. Record licensing obligations and whether to adopt, integrate, or implement independently.

Benchmark on the same versioned repository snapshots, tasks, permissions, budgets and environments where practical; use multiple runs/seeds, disclose unavailable competitors or mismatched models, and separate model capability from harness quality. Include issue resolution, tool reliability, edit correctness, repo onboarding, interrupted run recovery, long sessions, Git/CI remediation, browser verification, security boundaries and cost. Track pass@1, success with repair, wall-clock p50/p95, model calls/tokens, tool errors, wasted work, regressions, unsafe actions blocked and human intervention rate. Baseline ClawAI single-model before changes. Don't invent competitor test results.

Output: evidence-backed parity matrix and backlog; architecture tradeoffs; reproducible benchmark scripts/fixtures; testable release criteria. Revisit research when docs or versions change. See 12_RESEARCH_SEEDS.md for starting URLs; they are not an exhaustive investigation.

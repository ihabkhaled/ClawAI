# 05 — Optional three-model coding team

Implement optional collaboration using one user-selected primary model and zero, one or two supportive models, selectable from the current ClawAI chat model catalog (not hardcoded vendor/model names). Examples: Kimi as primary plus DeepSeek and GPT; Claude as primary plus GPT and Gemini. Names are illustrative; discover actual current model IDs and capabilities at runtime. Support BYOK/plan restrictions, provider availability, tool/vision/context capabilities, pricing, and data-sharing consent for each provider. Default single-model mode remains fast, inexpensive and fully functional. Offer optional always-consult mode for every meaningful task/prompt plus a recommended risk-adaptive mode. Explain cost before enabling; user can cancel, disable, change roles and set hard spending ceilings. Never silently send source or secrets to a different provider.

## Orchestration

Primary remains accountable for plan, implementation and final response. Supportive models are independent advisers/reviewers by default, with read-only scoped context and no external-write tools. On approved tasks, isolated subagents can propose patches in separate worktrees; primary integrates after diff review. Do not let three models concurrently mutate the same files. Run independent analysis first to avoid anchoring, then exchange concise structured findings, not raw private reasoning. The orchestrator determines what information is allowed to cross providers and sanitizes secrets; never broadcast full workspace by default.

Phases: understand requirements -> independent interpretations -> primary reconciles -> business and architecture plan -> peer risk/gap review -> implementation -> targeted independent code review -> test design -> verification/security/performance review -> final reconciliation. Involve advisers during real blockers, major design choices, risky changes, test gaps and final review; in always-consult mode get one bounded independent response per meaningful user request before decision. Supportive models propose findings with evidence, file references, confidence, impact, candidate fixes and test ideas. Primary may accept, reject or defer each suggestion with concise reason and verification; disagreements are not resolved by popularity. Independent deterministic tests, policy and evidence outrank all models. Escalate unresolved critical findings rather than merge. No model sees another provider's private instructions or can elevate authority. No open-ended debate: cap rounds (initial proposal: two review rounds per milestone, configurable within hard budgets), time and total tokens; terminate on useful convergence or no progress. Maintain an auditable decision ledger.

## Runtime and UX

Implement model capability adapters, normalized messages/tool calls, structured review schema, per-provider rate-limit handling, timeouts, partial availability, cancellation, fallback only with approved provider/data scope. Run independent reviews concurrently where safe. Show primary and adviser identities, phase, findings, accepted/rejected counts, budget/actual costs and limitations; do not present raw chain-of-thought. Keep UI responsive when an adviser fails. Reserve cost atomically before calls and reconcile actual provider usage; no hidden retries/overcharges. Distinguish provider failures, budget exhaustion and primary disagreement. Ensure optional mode cannot lower security thresholds or make release decisions. Add admin controls, per-user defaults, tenant restrictions and model availability updates.

## Evaluation

Compare single primary vs primary+1 vs primary+2 on identical tasks, budgets and repository versions; measure pass@1, defect escape, review precision/recall, regression, time, spend and human intervention. Include conflicting advice, fabricated findings, compromised adviser, duplicated findings, unavailable provider, long context, quota, code/privacy constraints, model without tool calling, adversarial inter-agent messages and unsupported schema. Do not claim 80% to 99% quality without controlled evidence. Report tradeoffs and confidence intervals where sample size permits. The feature succeeds if measured benefit justifies incremental spend in defined task classes, not because more models are involved.

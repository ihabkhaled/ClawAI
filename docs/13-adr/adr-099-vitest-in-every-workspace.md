# ADR-099 — Vitest in every workspace; Playwright stays for E2E

**Status:** Accepted · **Date:** 2026-09-19 (records a migration landed 2026-09-17) · **Supersedes:** [ADR-062](adr-062-testing-runner-retention.md) · **Services:** all 20 apps, all 6 shared packages

## Context

[ADR-062](adr-062-testing-runner-retention.md) (2026-07-24) kept three runners:
Jest (`ts-jest`) for NestJS services and shared packages, Vitest for the
frontend, Playwright for E2E. It did not forbid a migration; it asked for one to
be a deliberate decision with its own ADR.

The migration happened in commit `63e7f7806` (2026-09-17, "build: migrate every
workspace from Jest to Vitest, and typecheck on TypeScript 7"), with a CI
install fix in `fd88cb60a` the same day. The stated reason was gate cost: 26
workspaces and ~1,540 spec files had made the commit gates slow enough that
people avoided them — the point at which a gate stops working. This ADR records
that decision after the fact; no separate ADR was written at the time.

## Decision

- **Every workspace runs Vitest.** `test` is `vitest run --passWithNoTests`,
  `test:cov` is `vitest run --coverage`, `test:watch` is `vitest`. Jest,
  `ts-jest`, `babel-jest`, `@types/jest`, every `jest.config.*` and
  `babel.config.cjs` were removed.
- **Backend configs use `unplugin-swc`**, not Vitest's default esbuild
  transform. esbuild does not emit decorator metadata; without it
  `Test.createTestingModule` resolves every injected constructor parameter to
  `undefined` and DI fails silently. Configs were generated by
  `tools/migration/jest-to-vitest.mjs`.
- **Coverage** is `provider: 'v8'` (`@vitest/coverage-v8` — declared only by the
  frontend and coding-agent today, resolved by the others through npm hoisting),
  thresholds in `test.coverage.thresholds`
  of each `vitest.config.ts`. The floors carried over from the Jest configs; the
  ≥92 % flagship policy in rules 04/22 is unchanged.
- **Globals are on** (`globals: true`); types come from `src/vitest-globals.d.ts`
  (`/// <reference types="vitest/globals" />`), not a `types` entry.
- **`include: ['**/*.spec.ts']`**, matching Jest's old reach — a narrower
  `src/**` pattern silently dropped specs under `prisma/seeders/__tests__`.
- **Playwright stays** for browser E2E. Unchanged.
- **Gates stay runner-agnostic.** `tools/affected`, the hooks, and CI call each
  workspace's own `npm test`; rules describe behaviour, not runner identity.

## Consequences

- One test API (`vi.fn`, `vi.mock`, `vi.spyOn`, `Mocked<T>` from `vitest`)
  across the repo. Docs, rules and skills were updated to match in the same
  knowledge pass as this ADR.
- The migration surfaced four real defects (an untested `shared-types`, a lost
  setup file, an ignored `doNotFake` timer option, a dead in-test `vi.mock`);
  see the `63e7f7806` commit message.
- The ESM/CJS namespace-import trap (rule 13, item 6) is still **not** caught by
  unit tests: Vitest's default `deps.interopDefault` can mask it the way ts-jest's
  CommonJS output did. `tools/__tests__/esm-namespace-import-bindings.test.mjs`
  remains the guard.
- Known leftovers (code, not docs): `tools/lib/extractors.mjs` still falls back
  to `runner = 'jest'` for a NestJS workspace with no `vitest` dependency, and a
  few comments (e.g. `html-sanitiser.utility.ts`, the ESM namespace test) still
  describe Jest behaviour.

## Alternatives considered

- **Keep ADR-062's split.** Rejected by the migration itself — gate time had
  become the cost ADR-062 said a migration would need to justify.
- **esbuild transform with `emitDecoratorMetadata` workarounds.** Rejected;
  swc emits metadata directly.

## Rollback

Revert `63e7f7806` and `fd88cb60a`. Not planned.

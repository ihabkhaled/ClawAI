# ADR-207: Akinator is an in-app skill that runs on every change, with no command

**Status:** Accepted

**Date:** 2026-10-31

Builds on [rule 55](../../rules/55-akinator-station-discipline.md) and [ADR-170](adr-170-agents-md-is-the-canonical-router.md). New rule: [rule 65](../../rules/65-akinator-runs-on-every-change.md).

## Context

The owner's Akinator method (twelve stations: ask, resolve, audit, plan, implement, document, skillify, rule, contextify, memoize, index and sync, verify) was applied here only when the plugin was installed and invoked, or when rule 55 happened to be cited. A contributor without the plugin, a different tool, or an agent that forgot the slash command skipped it, and the owner had to repeat the instruction. Rule 55 and `skills/apply-akinator-without-the-plugin.md` described the method in ClawAI vocabulary but carried no procedure files, no tools and no trigger.

## Decision

- **Vendor the skill** into `skills/akinator/`: `SKILL.md`, every station reference, the owner's MIT license, and the read-only tools the procedure needs (`akinator_context`, `akinator_trace`, `akinator_sensitive`, `akinator_coverage`, `akinator_scope`, `akinator_version`, `akinator_ledger`, plus the two helpers they import). The in-repo copy is the source of truth for this repository; the plugin keeps working for the owner's own sessions.
- **Do not vendor the writers** (`akinator_wiki`, `build_brief`, `extract_*`, `akinator_distil`, `akinator_rules`). `.ai/` and `docs/wiki` are generated by `knowledge:build` and verified for freshness ([rule 24](../../rules/24-generated-files-and-knowledge-freshness.md)); a second writer would desync them. `akinator_context.py` caches under `.ai/local/` (gitignored), not `.ai/cache/`.
- **Make it mandatory with [rule 65](../../rules/65-akinator-runs-on-every-change.md):** every change, every agent, every tool runs the full pass without being asked; forgetting the command is never a reason to skip it.
- **Trigger it wherever a tool can be triggered:** `AGENTS.md` (the canonical router; the per-model routers are generated from it), `CLAUDE.md`, `cursor.md`, `.cursorrules`, a Claude Code project skill whose description matches every repository-changing prompt, and a `UserPromptSubmit` reminder in the project `.claude/settings.json`.
- **Keep the existing artifacts:** rule 55 stays as the non-negotiable subset, `skills/apply-akinator-without-the-plugin.md` stays as the ClawAI station-to-path runbook, `context/akinator-station-map.md` stays as the lookup.

## Alternatives considered

- **Link to the plugin repository instead of copying.** Rejected: an agent without network or without the plugin has nothing to read, and upstream edits would change this repository's behaviour silently.
- **Copy all sixteen scripts.** Rejected: the writers would regenerate `.ai/` and `docs/wiki` outside `knowledge:build`.
- **A git hook that runs the Python tools.** Rejected: hooks stay fast and already run the knowledge checks; the method is also a way of working, which no hook can check.
- **Enforce only by review.** Kept as the fallback; a CI check for a stated knowledge delta is a follow-up for the tooling owner.

## Consequences

- Every contributor, with or without the plugin, gets the same pass and the same tools from inside the repository.
- About twenty-five markdown files and nine Python files are now maintained here. Divergences from upstream are listed in `skills/akinator/SKILL.md` ("Divergences from upstream"); upstream updates are re-vendored by hand.
- `.claude/` is gitignored, so the project skill and hook only ship once the ignore rules allow `.claude/settings.json`, `.claude/skills/` and `.claude/hooks/`.
- The pass costs time on every change; the scope rule (a typo records `knowledge delta: none, because ...`) keeps it proportionate.

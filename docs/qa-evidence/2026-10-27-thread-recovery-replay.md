## Findings

Scenario families (50, each at least twice, en/ar/ja): clean success 3, OUTPUT_INVALID (wrong shape, truncated, reasoned-no-answer) 6, provider faults (429 with Retry-After, 502/503, CLOUD_PROVIDER_REQUEST_FAILED 400, idle timeout, PROVIDER_CREDIT_EXHAUSTED, 413) 13, judge/critic invalid JSON 4, REVIEW_NOT_PASSED 2 plus owner retry 3, all-providers-down 2, spend cap 2, cancellation 2, non-retryable entitlement/credit/safety 4, null-priced model 3, 4k-window 2, huge/single/emoji/RTL source 4.

Shipped behaviour of 128a8306a is in this tree: `generation-pipeline.manager.ts` throws `DeterministicGenerationError` after three rejected review rounds and `GenerationJobsService.retry` passes every author, the Judge and the Critic as changed roles after `REVIEW_NOT_PASSED`. The replay exercises both: an exhausted review fails on job attempt 1 (no redundant automatic retries); the owner retry inherits the research (0 research runs, one RESUMED_FROM_CHECKPOINT step) and makes fresh model calls for all five roles with none resumed. A control test with the pre-fix inheritance shows cached author replies replaying.

Bug found and fixed: a `SHRINK_SOURCE` rung after a provider 413 re-sent the same prompt when the first request had already been shrunk to fit the 200,000-character gateway limit (huge source: 121,751 characters refused, 121,868 re-sent). `RoleHealer.promptFor` now shrinks to the fit level plus the rung level. Focused test: scenario C12 and the regression test in the replay spec; C12 fails without the fix.

Modelling limits: the fake gateway does not enforce the spend cap, the per-model failure demotion between attempts (`modelSpecificFailures`) is empty, and the repository inheritance filter is mirrored in the fake store, not run against Postgres.

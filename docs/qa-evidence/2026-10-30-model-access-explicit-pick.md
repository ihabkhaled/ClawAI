## Findings

- Same defect in two other services, not fixed here: Threads (`recommended-team`, `healing-pool`, `generation-preflight`) and
  Workspace (`model-catalog-resolver`) call `isModelAllowedForUsage` with no cost class, so on a cost-class plan every
  model reads as "needs plan" there. They need a cost-class lookup first.
- The admin page lists one row per catalogue model in cost-class mode even though a default row does nothing; it is noise
  for the admin and is a follow-up (hide default rows).
- Local dev frontend returned a false 404 for the model-access route until the `.next/dev/cache` was cleared and the
  container restarted.
- Local `plugins/consent-requests` answers 502 (plugin-service is not running); unrelated.
- Production was not touched by hand. The fix reaches it through the normal deploy after the push.

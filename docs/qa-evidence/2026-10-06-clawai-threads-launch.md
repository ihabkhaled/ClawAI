## Findings

1. Every Threads UI string (owner portal, public article community, change requests, report form, publication-type options) showed its raw key (`threadPublicLike (2)`). The components called `t('threadX')` but the keys live in the `chat` namespace and `t()` returns a dotless key unchanged. Unit tests mocked `t` and could not see it. Fixed by namespacing the calls; `threads-translation-keys.test.ts` now resolves every key against all 13 real dictionaries. Three portal keys (`newThread`, `loadingThreads`, `noThreads`) had the same flaw; the create heading now uses a new `chat.threadCreateTitle`.
2. The public article page emitted no structured data. Added `Article` JSON-LD with the real sources as `citation` (never `ScholarlyArticle`, never peer-review wording).
3. Local `claw_threads` had drifted from the committed community migration (missing `accepted_revision_id`), so a change request returned 500. Not a repo defect (a fresh migration creates it); fixed locally with the column only.
4. The dev auth container was unhealthy on a stale baked shared-types. Its rebuild failed on a BOM in host-generated `src/generated/prisma/package.json` files (14 services); BOMs stripped (git-ignored files), rebuild succeeded.

5. The first live runs failed for four reasons found only by running real models: a schema/migration column mismatch (every job would have failed on a fresh or production database), consensus that needed byte-identical drafts, strict-JSON parsing that rejected fenced or mis-keyed answers, and failures that logged nothing. All four are fixed in the generation service with tests (71 pass), and a repo test now keeps Threads schemas and migrations in step.
6. Not fixed, owner decision: the job `stage` stays `AUTHOR_DRAFTS` through consensus and Judge (progress UI cannot show later stages); the owner form defaults to 4096 output tokens and lists models with unknown context windows, which the worker rejects (deepseek-v4.1-flash, glm-5.3-flash); reasoning models such as kimi-k2.6 can spend the whole budget thinking (`CLOUD_PROVIDER_EMPTY_RESPONSE`); three Judge rounds at threshold 80 rejected honest drafts built from blog and forum evidence.

7. The pack's primary entry point (an action inside the chat) did not exist; added and walked live: chat header menu -> modal (source fixed, topic from the chat title, consent box, start disabled until ticked, cloud models only) -> Start generation -> portal opened on `?publication=<id>` with the live Cancel control; cancel requested and acknowledged. Mobile 390: menu lists the action, no overflow. Screenshots `.playwright-mcp/thread-modal-{desktop,filled,mobile}.png`, `thread-portal-after-modal.png`. The ClawAI "Install" prompt (fixed, z-120) can sit over the modal's Start button on short viewports; not changed here.

## Findings

- ProviderStreamReader read Ollama's thinking only at the top of a frame (the /api/generate shape). /api/chat puts it in message.thinking, so a thinking-only chat stream folded to nothing. Fixed and tested; the chat surfaces stream Ollama Cloud through the buffered path, so it had not shown there.
- generateOnce sent no think field to Ollama while the chat path forces false: a reasoning model could spend its whole output budget thinking and return empty content. Both endpoints now send think:false unless the request sets thinking:true. Whether every Ollama Cloud model accepts a boolean (gpt-oss documents levels) is not verified; the chat path already sends it to all of them.
- Deleting the 8 legacy lint warnings in chat-execution.manager.ts required splitting execute into prepareExecution, skipChainCandidate, succeedChain and absorbChainFailure over a CandidateChainState, plus five smaller extractions. The full suite passed unchanged.
- undici's own 300 s header and body timers equal the idle limit. Our typed abort is armed first; if streams are ever seen to die at exactly 300 s with an anonymous abort, a dispatcher with both timers at 0 is the fix (needs the undici package).

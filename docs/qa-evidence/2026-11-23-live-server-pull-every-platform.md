## Findings

- A text-only model's refusal ("I'm sorry, but I cannot process audio files. My capabilities are limited to text-based interactions.") was published as a Live caption. file-service now classifies it as a model rejection and tries the next model, on the metered and platform-paid paths. Live DB: 1 of 14 captions before the fix, 0 of 30 after.
- yt-dlp returns HLS for recorded YouTube videos too; without `--match-filters is_live` a normal video link would have been "server pulled". Filtered.
- The public SEO descriptions said analysis was HLS-only and never YouTube (stale since batch 2). Rewritten in 13 locales.

## Open gaps

- L14 RTL browser pass with an Arabic account.
- Production verified after v1.240.0: live-service healthy, yt-dlp 2026.10.26 in the image, a live YouTube channel and a live Kick channel resolve to HLS (`m3u8_native`) from inside the production container. The active production policy has no stored list, so it defaults to every platform. A signed-in production caption run is still open.
- yt-dlp needs periodic version bumps as platforms change (both ARGs together).

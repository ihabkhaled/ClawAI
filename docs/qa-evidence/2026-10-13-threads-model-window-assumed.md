## Findings

- Root cause (from code, not from production logs): ModelContextClient treated `contextWindowTokens: null` as fatal, and the shared window table had no OLLAMA, OPENROUTER or GROQ rows. Fixed by assuming 32,768 tokens and failing only when the whole prompt does not fit.
- A second cause of waste: every error was retried three times. Deterministic errors now fail on attempt 1.
- Only the gpt-oss family got new table rows; the repository states no window for glm, qwen or mistral, so they use the assumed default.
- The old MODEL_CONTEXT_UNAVAILABLE code is no longer emitted but is still mapped in the frontend for steps stored earlier.

## Open gaps

- L03, L04, L05, L08, L09, L11, L13, L15 not run: they need the live stack and a deploy, which this change did not do. Deploy order: shared-utilities first, then thread-generation-service, then the frontend.
- The real window of OLLAMA glm-5.3, OPENROUTER mistral-small-2603 and GROQ qwen3.8 is still unknown to us. Until a catalog sync or an admin fills `router_model_registry`, they are held to 32k.

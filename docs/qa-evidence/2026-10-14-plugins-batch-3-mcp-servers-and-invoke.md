## Findings

- Found by the live run: a real page's `<!doctype html>` leaked into the extracted text. Fixed (declarations, CDATA openers and processing instructions are skipped) with a test.
- Found by review of the HTML reader: every `&` scanned to the end of the page for a `;`, which is quadratic on a hostile page. Fixed (a ten-character window), with a timing test over five pathological inputs.
- Found by the snapshot spec: a tool named `__proto__` was accepted (as `proto`). Refused now.
- Found by the client spec: a JSON-RPC error message over 2000 characters made the whole answer unparseable. The cap now applies after parsing.
- Found by the IP spec: a 12-digit octal host (`017700000001`) was not read by the legacy IPv4 parser. Widened. (The URL parser folds these forms before the guard sees them; the legacy parser is a second line of defence.)
- Found by the pentest list: userinfo and a numeric TLD fail with `USERINFO` / `UNPARSEABLE` rather than `IP_LITERAL`; still refused, expectations corrected.
- Design decision with a cost: the SSRF guard lives in the plugin service, not `shared-utilities`, because a new `@claw/shared-*` symbol crashes every dev container that bakes the packages. Moving it later is mechanical.
- `EntitlementsAdapter.reserveFeatureUsage` only names `FILE_GENERATION`, so the PLUGIN_CALLS hold uses its own small client for the same internal routes (`shared-entitlements` is outside this batch).
- The chat integration's existing `PluginInvokePort` expects `POST /internal/plugins/invoke`; this batch ships `POST /api/v1/plugins/invoke` with the caller's JWT as asked. The mapping is in the service guide.

## Open gaps

- L03, L05, L06: the new routes were not exercised on the live stack; whoever deploys this build runs the curl lane (register a server, refresh, invoke as Free, Pro and admin) and the SSRF list against the running service.
- L08, L09: owner walk-through; admin approval queue, host rules, OAuth2 PKCE and the consent channel are batch 4 or later. Until the approval routes exist, leave `userServers.requireApproval` off.
- L13: no load test of the egress path.
- L15: run `knowledge:build`, read the GitHub gates after the push.
- nginx: the default 60 s `proxy_read_timeout` on `/api/v1/plugins` is shorter than a 60 s tool plus handshake; irrelevant for chat-service (it calls the service directly) but relevant if the browser ever invokes a tool.

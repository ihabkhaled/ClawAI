## Findings

- The automated security review found DOCX reached mammoth with no archive bounds. A header screen in front of mammoth was the first fix and was rejected in turn (a declared-size check is not the same archive the inflater reads, and a repeated entry name hides a part), so DOCX now uses the bounded reader and mammoth is off this path. A pre-existing lint warning in `ooxml-parser.utility.ts` had to be fixed because the file is now touched.
- The review then found the text regexes themselves were quadratic on unclosed openers, in this new DOCX code and in the older XLSX and PPTX code now reachable through this endpoint. All of them now use one forward-only scan; 6 timing cases (600,000 unclosed openers per reader) and 12 scanner cases cover it.
- A first RTF fixture I wrote held raw control characters instead of backslashes and read back as garbage;
  it was my fixture, not the parser. Rebuilt with real backslashes and it reads correctly.

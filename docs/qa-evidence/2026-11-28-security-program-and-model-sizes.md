## Findings

- Prod: openssh/openssl/libc/sudo security updates were pending with automatic upgrades off; installed and switched on.
- Prod: two `.env` backups were world-readable; locked to 600.
- Prod: Firecrawl Redis had no password and its RabbitMQ the default `guest` user, on a network shared with three headless
  browsers; passwords added (repo + prod `.env`), applied at the deploy.
- Prod: scanner URLs got a ~470-940 KB Next 404 (amplification); nginx now answers them with 146 B.
- IPv6 visitors reach nginx through Docker's proxy as `172.x`, which no rate limit or ban can key on; prod nginx now
  publishes IPv4 only (no AAAA record exists).
- Prod model registry last synced 2026-08-30: OpenAI, Gemini, Anthropic and Grok rows have no context window; a sync after
  the deploy fills them.
- Local Ollama rows had no window (ollama-service never read `/api/show`) and llamacpp forwarded a 32,768 placeholder as a real
  window; both fixed (ADR-234 addendum).
- Router-model PATCH reset every defaulted field (zod `.partial()` keeps defaults); fixed with `updateSchemaOf`.
- Local gitleaks 8.24.3 ignored the repo's `[[allowlists]]`; upgraded to 8.30.1.
- The dev auth-service crash-looped mid-work (DI token from a `Pick<>` type); fixed and covered by a wiring spec.

## Open gaps

- `admin-modules.spec.ts` "plan pricing" fails on a missing 'Billing period' field; pre-existing, billing admin untouched here.
- Other services do not yet report SSRF refusals or their own 429/403 to the abuse endpoint; no admin screen for the
  `security.abuse.*` settings (API only); no retention job for `abuse_signals`.
- A prod reboot for the new kernel and libc waits for the owner.

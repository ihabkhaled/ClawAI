## Findings

- The 503 for a foreign source thread came from `ChatSnapshotClient`, which turned chat-service's 404 into a 503. Fixed there; Threads relays 404 `Source thread not found`.
- The Free-plan 403 is two separate gates. The generic text came from auth-service's budget step (permission and three plan features) and was flattened twice. The per-model plan gate did not exist at enqueue; it only ran later in chat-service. Added at enqueue with the same test chat uses.
- The review prompt never carried the requested locale, so the Judge saw an English topic and a Spanish draft. Fixed in the system prompt.

## Open gaps

- L03, L05, L08 NOT_RUN: need the live stack after deploy; the release owner closes them with a Free, a Pro and an Admin account.
- L13 NOT_RUN: not load-measured.
- L14 NOT_RUN: the frontend must map `MODEL_NOT_ALLOWED_FOR_PLAN`, `THREAD_MODEL_UNKNOWN`, `THREAD_SPEND_CAP_TOO_LOW`, `THREAD_GENERATION_NOT_PERMITTED` and `THREAD_GENERATION_NOT_IN_PLAN` to translated sentences in all 13 locales; it currently shows one generic sentence for any 403 on start.
- Not done: the retry route's `models` overrides are not checked against the catalog or the plan; the revision-review enqueue is unchanged.

## Findings

- Production chat failure for the four new providers: chat-service posts to `<base>/chat/completions`; host-only base URLs 404. Fixed as data: per-provider chat path folded into the execution base URL.
- NVIDIA NIM lists models the key cannot call; classified as model-unavailable so the existing retire-after-three mechanism removes them.
- Custom providers showed `CUSTOM_OPENAI_COMPATIBLE` in the model rows, exposure table, connector detail and public catalog; they now carry their own name.
- Model ids over 128 characters could not be exposed; sync now leaves them out.
- `*.snap` showed as modified after every vitest run (LF vs CRLF); `.gitattributes` pins LF.
- Connector-service was crash-looping on unapplied migrations; PATCH reset omitted defaulted fields.- Connector-service was crash-looping: two unapplied migrations and a stale Prisma client. Applied and regenerated; this was why AI requests failed.
- PATCH reset every omitted defaulted field (zod `.partial()` keeps `.default()`), silently wiping `apikey` header and checkboxes. Fixed in the update schema with a test.
- Pollinations 0 models: `capabilities` is a list; every entry failed to parse. AI Horde 0 models: bare list names models with `name`, default list is image-only (`?type=text`).
- Edit/stuck form and empty checkboxes: uncontrolled inputs were not remounted; fixed by keying the form per provider.

## Findings

- The labs and Compare lacked the chat composer's Context button and Prompt library; Compare used a bare textarea. Fixed.
- Ten copies of thread creation, none ownership-checked for a supplied threadId. Fixed (one resolver, 403).
- No product bug found by the browser lanes: Context and Prompt library fit at every width on the labs, Compare and the in-thread panel.
- Free users cannot read or create context packs (CONTEXT_PACK_READ_OWN) and are plan-gated on the labs before any thread check; the thread ownership check (403 FORBIDDEN_THREAD_ACCESS) is proven with admin as the intruder on a free user's thread.
- Environment, not this batch: another session's uncommitted connector-provider work in apps/claw-connector-service (also routing and frontend connectors) crashed claw-connector-service in the dev stack (`app crashed`, TS errors in provider-definitions.service.ts); models-snapshot then returned `fetch failed` and model calls failed from about 16:08. A restart did not clear it. Not touched here.
- The auth register and login endpoints rate limit hard (429, Retry-After up to 1215 s); QA scripts must log in once and register at most once.
- Cleanup, through the API: the lab threads, packs (`qa-parity-*`, `E2E lab parity pack`) and the probe thread created by these runs were deleted (every DELETE returned 200). User delete is a soft delete: 5 throwaway `qa-lane-a-*@claw.local` users created by my first scripts are now SUSPENDED rows and cannot be removed through the API. The cleanup also removed 18 empty Untitled threads of the admin account created today by this and the earlier QA runs.

## Findings

- Gemini is a credit connector in this deployment, so with PAYG on a Free user's Gemini call takes the free-allowance
  path (platform-absorbed, with its own per-request ceiling), not the branch that now carries the plan limits.
  The plan limits bite for platform-paid calls only.
- The daily token quota check (chat-service) counts the default 30,512-token output ceiling and runs first, so on
  Free a prompt over about 19,000 tokens is refused as `QUOTA_DAILY_EXCEEDED` before the plan limit is reached.
- The fallback chain meets the refusal on a later candidate (GROK/grok-3-mini in the live run) and the 402 ends the chain,
  so the user sees the plan-limit message.
- Gemini kept answering 429 (busy) during the session, so no priced paid answer settled.
- Environment: creating a test user needed `status = ACTIVE` as well as `email_verified_at`; the test user and its
  threads remain in the local dev database.

## Open gaps

- L04 and L08: the refusal in the chat UI, which needs a Free-plan-selectable platform-paid model or a plan editor.
- The admin plan editor does not show the three fields yet.
- Parent budgets for Compare, Judge and fallback chains; refusing unpriced models on paid plans (owner decision).
- L15: GitHub gates after the push.

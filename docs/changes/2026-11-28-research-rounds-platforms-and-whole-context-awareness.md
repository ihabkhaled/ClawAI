## Before

- Chat research was one search pass. No source registry, no evidence store, no follow-up reuse.
- Research planned from the current message only. A lyric lookup failed six turns in a row, and a saved memory was not
  found from a new chat.
- Context matching kept only Latin letters, so non-Latin words were dropped.
- Web text reached the model without an untrusted-data fence.

## Change

- Research runs in rounds with per-depth budgets, a gap check and Stop carried to the answer (ADR-224).
- A platform registry with free official APIs and site-scoped search, plus an admin page (ADR-225).
- Every turn plans from the whole chat and saved memories; memory is never filtered; matching is Unicode-aware;
  text lookups search the exact words; citation markers are normalised (ADR-226).
- The public research page gained new sections, a video and a screenshot in 13 locales (rule 66).

## Why

Owner reports of 2026-11-28: search was far weaker than a plain web search, new messages ignored the chat, and a saved
secret was invisible until the owner pointed at memory. The owner asked for the most accurate and context-aware search.

## Verification

See the QA record. Unit suites for the three services and the frontend, typecheck and build passed. Live local checks:
the owner's five lyric turns name the song and band every time; plan gates hold for a plan without research.

## What would make this stale

A change to the research round budgets, the platform registry schema, memory selection limits, or the context token
rules. Known gaps: Compare, Consensus and the labs still plan research from markers; a model that only announces a
search is not yet continued.

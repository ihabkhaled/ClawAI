# Akinator is now part of the app's own skills, rules and docs

The Akinator method (twelve stations, one pass) is vendored into the repository and runs on every change without a command
([ADR-207](../13-adr/adr-207-akinator-is-an-in-app-skill-that-runs-on-every-change.md), [rule 65](../../rules/65-akinator-runs-on-every-change.md)).

- Added `skills/akinator/`: `SKILL.md`, 23 station references, the owner's MIT `LICENSE`, and the read-only tools
  `akinator_context`, `akinator_trace`, `akinator_sensitive`, `akinator_coverage`, `akinator_scope`, `akinator_version`, `akinator_ledger`
  and their helpers `extract_libraries`, `extract_stack`. Run them with `python -I skills/akinator/scripts/<tool>.py`.
- Not vendored: the writers (`akinator_wiki`, `build_brief`, `extract_*` generators, `akinator_distil`, `akinator_rules`), because `.ai/` and
  `docs/wiki` are generated by `knowledge:build`. `akinator_context.py` caches to `.ai/local/akinator-context-index.json`.
- Auto-trigger: `AGENTS.md`, `CLAUDE.md`, `cursor.md`, `.cursorrules`; a Claude Code project skill `.claude/skills/akinator/SKILL.md`; a
  `UserPromptSubmit` reminder in `.claude/settings.json` (script `.claude/hooks/akinator-reminder.mjs`).
- Indexed: `skills/00-index.md`, `rules/README.md`, `rules/00-master-rules.md`, `context/akinator-always-on.md` (linked from `context/README.md`).
- Open: `.gitignore` ignores `.claude/`; the lead must allow `.claude/settings.json`, `.claude/skills/` and `.claude/hooks/` for the project
  skill and hook to be committed.
- Open: a CI check that a feat or fix states its knowledge delta (tooling owner).

knowledge delta: this note, ADR-207, rules/65, skills/akinator, context/akinator-always-on.md, the router files.

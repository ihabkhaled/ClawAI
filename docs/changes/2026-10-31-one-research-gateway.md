# 2026-10-31: One research gateway for every chat surface

- New `utilities/research-gateway.utility.ts` is the only research client in chat-service. Compare and the nine orchestration managers (via `ResearchEnricherManager`), search-first, AUTO research, the explicit modes, labs/gateway context and the `web_search` / `web_fetch` tools all go through it. The five private clients are gone.
- One set of timeouts (`research-client.constants.ts`): search 24 s, fetch phase 36 s, whole run 60 s, all strictly above research-service's own bounds (20 s / 30 s). The old 8 s and 15 s callers cut slow providers off.
- The answer starts only after the gateway returned. A search that fails or times out is announced (`RESEARCH_FAILED`, transcript warning `research.searchTimedOut` / `research.searchFailed:<KIND>`) and the model answers with what there is.
- Richer evidence: 10 merged results, 6 pages fetched in parallel, per-source ceilings 6,000 / 8,000 chars, provenance `(found by ...)`, all fitted to 45% of the window (16,384-token assumed window when the caller does not know the model's). Dropped sources are announced.
- `providers[]` / `mode` from research-service are read when present; absent means the old shape. `SEARCH_DONE` narration gets `providers` and `providerCount` params.
- `web_search` tool: configured providers (all, parallel) first; the hosted Ollama search only when research-service is down or has no provider. Independent tool calls of one model turn run in parallel (limit 4), results in call order.
- Search-first: service-token route (it sent no token before) and skipped when the turn already has research evidence.
- Metering: unchanged units, counted once. research-service records one unit per provider call; chat adds none on the research path.
- Guards: `research-gateway-parity.spec.ts`, `research-wait-before-model.spec.ts`, `research-gateway.utility.spec.ts`, `research-web-search-tool.utility.spec.ts`, `bounded-parallel.utility.spec.ts`.
- Live check on https://claw.local, 2026-10-31 (providers: Ollama Web Search + SerpAPI). Normal chat, run route: `run: start` 13:36:13, settled 13:36:22, `research_completed` 13:36:22, router and model start 13:36:22-23. - Needs frontend strings (the locale files are not touched here): `narration.searchDoneWithProviders` "Searched with {providers}: {count} source(s) read" (params `providers`, `providerCount`, `count`); a label for the transcript warnings `research.searchTimedOut` "The web search took too long, so this answer may be missing sources." and `research.searchFailed` "The web search failed, so this answer may be missing sources."

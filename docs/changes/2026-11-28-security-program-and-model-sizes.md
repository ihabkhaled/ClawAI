## Before

GitHub's "Knowledge integrity" gate was red and a critical code-scanning alert was open. No skill or rule made every
change scan dependencies, code and secrets, and pre-push audited nothing. nginx trusted any crawler User-Agent, rendered
a full Next page for scanner probes, and had no general per-address budget. fail2ban lived only on the host. An abusive
signed-in account was never suspended. Firecrawl's Redis had no password and its RabbitMQ used `guest`. Model lists showed
no size. On the prod host, security updates were pending with automatic upgrades off and the host INPUT chain was open.

## Change

Rule 69 + skill secure-every-change, `npm run security:check`, a pre-push security step, OSV-Scanner and a weekly
full-history gitleaks scan (ADR-232 is the edge, ADR-233 accounts, ADR-234 model sizes). nginx verifies crawlers by
their operators' published ranges, refuses and bans fakes, answers scanner probes itself, and has general, static and
crawler budgets; fail2ban files are in the repo; prod nginx is IPv4 only. auth-service suspends an account that attacks
from its own session (1 h, 24 h, 7 d), never its victim, and blocks sign-up from banned devices; session-closing gaps
fixed. Every model list shows context and parameter size; local runtimes report both. Router-model PATCH no longer
resets defaulted fields. The prod host got its security updates, automatic security upgrades, a host firewall, SSH and
sysctl hardening.

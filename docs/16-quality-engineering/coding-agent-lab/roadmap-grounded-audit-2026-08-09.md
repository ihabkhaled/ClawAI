# ClawAI Coding Agent — roadmap, grounded against the codebase

A roadmap proposal was submitted for this extension. It was written without
reading the code and says so ("typical limitations I deduce"). Six auditors
checked every proposed capability against the real tree at v0.57.2, and a
seventh synthesised the result below.

The short version: most of what the proposal asks for already ships. The real
gaps are smaller, different, and in several cases are one hardcoded line rather
than a missing subsystem. Evidence is cited as `path:line` throughout.

Generated 2026-08-09 by a 7-agent audit over `apps/claw-coding-agent` and the
Runtime V2 loop in `apps/claw-chat-service`.

---

## Verdict — what the proposal got wrong

The proposal was written by deduction, and deduction lost. Paths below are relative to `d:/Freelance/Claw/apps/claw-coding-agent` unless prefixed.

1. **"Add a repo map / symbol index."** One exists and is registered in the live tool catalog under the name _workspace intelligence_ — `src/core/workspace-intelligence-graph.ts:17` (14 node kinds), `:61-73` (11 edge relations), builder `src/infrastructure/vscode-intelligence-index.ts:44`, tool `src/infrastructure/intelligence-tool-executor.ts:12`, registered `src/services/vscode-runtime-studio.ts:381`. Anyone grepping `repoMap`/`symbolIndex`/`codemap` finds nothing and concludes ABSENT. The real defect is not absence — it is that the tool cannot return a result on any repo with >100 nodes (`src/core/runtime/runtime-json-value.ts:7`, `MAX_RUNTIME_JSON_ENTRIES = 100`, enforced at `src/services/runtime-tool-dispatcher.ts:54`, failing as `TOOL_OUTPUT_INVALID` at `:340`).

2. **"Add a task-graph planner."** Both halves ship. A 10-stage delivery machine with a re-plan loop: `src/core/flagship-delivery.ts:5-16`, `src/services/flagship-delivery-service.ts:114-115`. A read-only PLAN mode enforced at the policy rail: `src/core/policy-v2.ts:110-111` (`PLAN_READ_ONLY`). A real concurrent DAG scheduler with per-node states `queued|running|paused|succeeded|failed|cancelled|blocked`, cycle detection, write-set collision detection and dependency-failure propagation: `src/core/multi-agent-dag.ts:55-105`, `src/services/sub-agent-coordinator-service.ts:89-99`, `:237-258`. What is missing is persistence of node state and a UI, not the planner.

3. **"Add multi-agent team mode with a reviewer persona."** Shipped, including git-worktree isolation per agent. `src/core/multi-agent-dag.ts:5-13` already enumerates `explorer|implementer|tester|reviewer|security-reviewer|documenter|integrator`; `src/infrastructure/vscode-sub-agent-worktree-adapter.ts:38` runs `git worktree add -b clawai/<taskId>-<uuid>`; each sub-agent is a real nested model loop with its own thread (`src/services/runtime-sub-agent-executor.ts:52-55`). There is no "legacy scanner" persona and roles are a fixed zod enum — that is the only true delta. The actual defect is that sub-agent work is invisible: the observers are literally `{ status: () => undefined, outcome: () => undefined }` (`src/services/vscode-runtime-studio.ts:312`) and each nested run gets `eventSink: { publishBatch: () => undefined }` (`src/services/runtime-sub-agent-executor.ts:63`).

4. **"Add a cost-tiered model router."** Multi-provider selection, local Ollama + llama.cpp as first-class peers of hosted models, and per-task model policy honoured at execution all ship with **no gap**: `src/core/model-catalog.ts:156`, `:90`, `:127`, `src/services/runtime-sub-agent-executor.ts:51-57`. The missing piece is one hardcoded literal — every flagship stage pins `allowedProviders: ['AUTO'], allowedModels: ['AUTO']` at `src/services/runtime-flagship-stage-adapter.ts:269-274`. That is a policy line, not a router.

5. **"Add effort/budget modes."** Six rungs, wired end to end and enforced on both sides of the wire: `src/core/effort-mode.ts:25`, `:60`, consumed at `src/services/runtime-studio-execution.ts:95-96,145`, enforced locally at `src/core/runtime/runtime-run-budget.ts:74` and server-side at `apps/claw-chat-service/src/modules/chat-messages/managers/runtime-v2-loop.manager.ts:353`. Status PRESENT, gap `none`. Note the shipped default is the _most_ expensive rung (`clawAI.effortMode` default `ULTRA`, `package.json:250`).

6. **"Add commit message generation."** The agent already commits with a model-authored message gated on a reviewed staged diff and a secret scan: `src/core/git-operation.ts:65-68`, `src/services/git-agent-service.ts:26-36`. What is missing is a _surface_ (command / SCM input box) — a UI affordance, not a subsystem.

7. **"Add bounded file reads / a tool catalog / path safety / workspace trust / rollback."** All PRESENT with gap `none`: `src/infrastructure/vscode-filesystem-tool-executor.ts:42-50` (line-range + `maxBytes` + returned `hash`), `src/core/runtime/runtime-tool-contracts.ts:42` (17 registered tools with JSON Schemas, rendered into the system prompt at `apps/claw-chat-service/src/modules/chat-messages/utilities/runtime-v2-model-output.utility.ts:28-41`), `src/core/workspace-path-policy.ts:48,64,115` + symlink-escape containment `src/core/workspace-file-containment.ts:8`, `package.json:37-45` + `src/core/policy-v2.ts:103` (`WORKSPACE_UNTRUSTED`), and two-phase transactional apply with hash+buffer-version preconditions and inverse-edit rollback (`src/services/file-transaction-service.ts:131-160`, `src/infrastructure/vscode-file-transaction-adapter.ts:170-191`).

8. **"Add error recovery so a failed tool doesn't kill the run."** PRESENT and the most deliberately engineered thing in the codebase, with the regressions it fixed written into the source: `src/services/runtime-tool-dispatcher.ts:284-327`, `:448-475`, `src/services/runtime-run-service.ts:106-114`. Malformed model output repair is likewise bounded and implemented twice (`src/services/agent-run-service.ts:267-286`; `apps/claw-chat-service/.../runtime-v2-loop.manager.ts:568-620`).

The proposal's one genuinely correct call: **semantic/AST validation of a produced diff does not exist**, in any form, in any language.

## What is genuinely missing

Only ABSENT and PARTIAL items appear here. Defects that sit _inside_ a shipped PRESENT capability — the Runtime V2 command allowlist hole, the empty approval card, the stale trust manifest, the unwired `enterprise-policy.ts` — are gaps on working features and appear in the roadmap instead.

**1. `workspace.intelligence` cannot return a payload (S).** `refresh` returns `{graph:{nodes,edges}}` and `query` returns `{result:{nodes,edges,unwired}}`, both unbounded; `src/core/runtime/runtime-json-value.ts:7,34` caps every array at 100 entries and `src/services/runtime-tool-dispatcher.ts:340` rejects the rest as `TOOL_OUTPUT_INVALID`. For this codebase specifically: this is the agent's only structural view of a monorepo with 18 services, so on the benchmark repo the tool fails on the first call and the agent falls back to blind `glob`+`search`. Add cursor pagination and result ranking to the executor. Do **not** raise `MAX_RUNTIME_JSON_ENTRIES` — it bounds every tool. Bundle the `identity.fileSetHash` fix (`src/infrastructure/intelligence-tool-executor.ts:24-32` demands a 64-hex digest the model cannot know, which `src/infrastructure/vscode-intelligence-index.ts:95-103` then overwrites).

**2. The watcher does not invalidate what is served (S).** `src/infrastructure/vscode-intelligence-index.ts:113` marks a dirty-set entry; the graph the model receives is cached at `src/services/workspace-intelligence-service.ts:17` and only dropped by `:34-37`, which the watcher never calls. During a multi-file feature the agent edits files and then queries a pre-edit graph. Also add debouncing (there is no timer anywhere in that file) and filter the `'**/*'` watcher glob to match `build()`'s exclusions at `:73`.

**3. No index persistence (M).** `parsed` is a `Map` cleared on `dispose()` (`:45`, `:123`). Every window re-crawls up to 50,000 files before the first query. The persistence pattern already exists next door (`src/infrastructure/vscode-run-journal-adapter.ts:15`, `src/services/global-context-service.ts:23`) and the cache-identity type is already written (`src/core/workspace-intelligence-graph.ts:89,97`).

**4. No find-usages, no import graph, no language-service integration (M).** `references`/`calls`/`depends-on` are declared at `src/core/workspace-intelligence-graph.ts:61-73` and never emitted — only `'declares'` (`vscode-intelligence-index.ts:168`) and `'routes-to'` (`:190`). The extension never calls `executeDefinitionProvider` / `executeReferenceProvider` / `executeDocumentSymbolProvider`. For a NestJS + Next.js monorepo where one DTO change fans out across a service, a controller, a shared package and 13 locale files, "who calls this" is the single most valuable missing fact.

## Sequencing note

Ship items 1–5 first, in order: they are the difference between an agent that can locate code and know it broke the build, and one that greps blindly and declares success. Items 1 and 3 are near-trivial and currently make the repo map return an error on every real repository; item 2 buys free typecheck and lint from language servers already running in-process; items 4 and 5 close the verification loop using primitives (`QualityRepairBudget`, `parseQualityDiagnostics`) that are already written, gated and merely uncalled. Hold items 16–20 entirely, and hold 11–15 until after a benchmark run — per-hunk review and a semantic diff linter both add cost to a system being measured on autonomous completion, and persistence, resume and cost tiering only start paying off once runs are long enough and correct enough to be worth resuming.
